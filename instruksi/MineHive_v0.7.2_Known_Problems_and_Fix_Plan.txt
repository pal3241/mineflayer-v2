MINEHIVE v0.7.2 — UNIVERSAL AUTOMATIC ITEM ACQUISITION
KNOWN PROBLEMS / REVIEW FINDINGS / FIX PLAN
============================================================

Project:
MineHive / mineflayer-v2

Target Version:
0.7.2

Review Focus:
Universal Automatic Item Acquisition

Tujuan dokumen:
Mencatat seluruh masalah, gap, bug semantics, kekurangan wiring,
dan pekerjaan lanjutan yang ditemukan saat review implementasi
MineHive 0.7.2 agar dapat diperbaiki secara sistematis.

============================================================
1. RINGKASAN KONDISI
============================================================

MineHive 0.7.2 sudah memiliki fondasi:

- AcquisitionService
- requirement normalization
- ITEM requirement
- TOOL requirement
- inventory resolver dasar
- storage lookup dasar
- fleet donor lookup dasar
- craft planning dasar
- smelt planning dasar
- collection planning dasar
- runtime settings
- environment configuration
- dashboard settings
- health registration
- application container registration
- version 0.7.2

Namun implementasi saat ini lebih tepat disebut:

UNIVERSAL ACQUISITION FOUNDATION

atau:

ACQUISITION PLANNER / RESOLVER MVP

Belum sepenuhnya:

UNIVERSAL AUTOMATIC ITEM ACQUISITION END-TO-END

Masalah terbesar:

Service baru sudah ada,
tetapi real task masih banyak menggunakan acquisition logic lama
yang berada di FleetCoordinator.

============================================================
2. P0 — ACQUISITION SERVICE BELUM DIPAKAI REAL TASK
============================================================

Application sudah membuat:

this.acquisition = createAcquisitionService(...)

Tetapi FleetCoordinator masih menggunakan private logic lama:

#ensureToolForBlock()
#ensureEquipment()
#prepareCraft()
#prepareSmelt()
#acquireItem()
#borrowNearest()

Akibatnya:

OLD SYSTEM:
FleetCoordinator private methods
    |
    v
REAL TASK EXECUTION

NEW SYSTEM:
AcquisitionService
    |
    v
mostly standalone planner

Masalah:

- logic menjadi duplikat
- behavior bisa berbeda
- bug dapat diperbaiki di satu sistem tetapi tetap ada di sistem lain
- 0.7.2 belum universal
- subsystem lain belum benar-benar memakai AcquisitionService

============================================================

============================================================

Target:

Task / Coordinator / Autonomy / Subsystem
                 |
                 v
          AcquisitionService

5. P0 — INVALID REQUESTER FALLBACK KE BOT PERTAMA
============================================================

Current behavior secara konsep:

Contoh:

Padahal seharusnya:

atau:

Jangan pernah menjalankan acquisition untuk bot yang salah.

============================================================

    throw NotFoundError
