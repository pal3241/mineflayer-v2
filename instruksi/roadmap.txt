MINEHIVE DEVELOPMENT PLAN
ROADMAP 0.7.x -> 0.8.x -> 0.9.x
================================

Project:
pal3241/mineflayer-v2

Tujuan dokumen:
Dokumen ini menjadi acuan kerja offline untuk melanjutkan pengembangan MineHive berdasarkan diskusi perencanaan versi, logistik, territory, shared memory, dashboard, testing, dan failsafe.

============================================================
1. STRATEGI VERSIONING
============================================================

MineHive masih berada pada fase pre-1.0, sehingga pola versi yang digunakan:

0.X.0
= milestone besar / subsystem utama baru

0.X.Y
= bug fix, optimisasi, reliability improvement, dashboard improvement,
  atau small feature yang masih berada di milestone yang sama

Roadmap sementara:

0.6.0
- Intelligence Foundation
- Semantic Memory
- ML
- HiveMind
- SQLite
- Safe Autonomy

0.7.0
- Logistics Foundation
- Stabilization
- Bug fixing
- Optimization
- Testing
- Dashboard experimentation

0.7.1
- Advanced Logistics Upgrade

0.7.2+
- Dapat digunakan untuk bug fix atau small update tambahan jika diperlukan

0.8.0
- Autonomous Territory System

0.8.x
- Territory, exploration, defense, failsafe, dan integration improvements

0.9.0 (candidate)
- Unified Hive Shared Memory
- Full short-term / long-term shared memory
- Dapat berubah jika muncul subsystem besar lain sebelum memory

1.0.0
- Target stable autonomous MineHive

Catatan:
Roadmap tidak harus kaku.
Jika fitur besar baru dibutuhkan di tengah pengembangan, nomor versi dapat disisipkan.

Contoh:
0.8.0 Territory
0.9.0 Defense
0.10.0 Shared Memory
1.0.0 Stable

============================================================
4. BUG / EDGE CASE YANG HARUS DITEST
============================================================

Tambahkan pengujian terhadap:

- bot disconnect ketika membawa item
- bot mati ketika membawa item
- bot disconnect ketika storage sedang terkunci
- chest dihancurkan
- chest berubah menjadi tidak valid
- chest penuh
- item tidak ditemukan
- inventory player/bot penuh
- inventory storage berubah karena player
- dua courier memakai chest yang sama
- dua bot mencoba reserve item yang sama
- reservation expired saat courier sedang bergerak
- pathfinding gagal
- storage tidak bisa dijangkau
- bot stuck
- HiveMind unavailable
- database unavailable
- repository operation gagal
- task dibatalkan saat transfer
- transfer hanya berhasil sebagian
- destination penuh
- source berubah sejak reservation dibuat
- bot reconnect setelah transfer gagal

============================================================
19. CONFIDENCE THRESHOLD
============================================================

Proposal LLM dapat memiliki confidence:

{
  "decision": "CREATE_WAREHOUSE",
  "region": "north-east",
  "confidence": 0.83
}

Policy contoh:

confidence >= 0.80
-> autonomous execution allowed

0.60 - 0.79
-> additional HiveMind evaluation

< 0.60
-> deterministic fallback

High-impact actions:

- abandon base
- destroy warehouse
- move colony
- large territory expansion
- remove critical infrastructure

dapat membutuhkan:

HUMAN APPROVAL
