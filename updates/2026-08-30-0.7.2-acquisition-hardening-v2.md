# 2026-08-30 - 0.7.2 Acquisition Hardening v2

## Perubahan

- Source planning sekarang memakai shortage, sehingga inventory yang sudah tersedia tidak diambil ulang.
- `maxSubtasks` membatasi jumlah dependency acquisition, bukan jumlah item yang diminta.
- Fleet plan selalu membawa item terpilih dan count shortage.
- Fleet donor difilter berdasarkan server, dimension, status, workload, dan surplus; handoff memakai meeting point serta verifikasi drop/pickup.
- Storage dan fleet hanya mempublikasikan event planning saat resolver memilih sumber; event `acquisition.completed` diterbitkan setelah execution dan verification berhasil.
- TOOL acquisition memilih tier yang memenuhi minimum tier, memprioritaskan tool murah saat preservation aktif, dan dapat mengeksekusi dependency craft.
- Craft, smelt, dan collect membagi operasi menjadi batch maksimum 64 item.
- Collection mencoba kandidat source berikutnya saat kandidat sebelumnya gagal.
- `allowPartial` mencatat status `PARTIAL`, jumlah collected, dan remaining shortage.
- Lifecycle request dan metrik completed/partial diperbarui setelah execution.
