# 2026-08-30 - 0.7.2 Runtime Acquisition Wiring

## Perubahan

- `Application` sekarang mengirim instance `AcquisitionService` yang sama ke `FleetCoordinator`.
- `FleetCoordinator` tidak lagi menganggap status planner seperti `STORAGE_FOUND`, `FLEET_DONOR_SELECTED`, atau `CRAFT_PLAN_CREATED` sebagai item yang sudah berpindah ke inventory.
- Adapter craft mengembalikan `craftable: false` untuk item tanpa recipe, sehingga resolver dapat melanjutkan ke smelt atau collect.
- Request ID dibuat saat record request dibuat, bukan saat normalisasi requirement.
- `maxAttempts`, minimum tier tool, agregasi inventory, urutan storage, dan metrik lifecycle request diperketat.
- Ditambahkan regression test untuk wiring Application dan bypass item non-craftable.

## Batasan yang masih eksplisit

Storage dan fleet pada `AcquisitionService` masih menghasilkan plan/selection. Eksekusi transfer tetap memakai primitive logistics dan handoff yang sudah ada di coordinator; service belum dipromosikan sebagai executor end-to-end untuk kedua sumber tersebut.
