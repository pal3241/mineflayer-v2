# 0.7.0 — Logistik Foundation

Release `0.7.0` membangun fondasi penyimpanan dan perpindahan item yang transaksional, terverifikasi, serta dapat diaudit. Scope release mengikuti fase `0.7.0` di `instruksi/roadmap.txt`.

## Perubahan utama

- Storage registry dipisahkan berdasarkan server dan dimension.
- Reservation aktif mencegah stok yang sama dialokasikan lebih dari sekali.
- Reservation yang kedaluwarsa dilepas otomatis sebelum transaksi dimulai.
- Reservation yang kedaluwarsa saat transfer berjalan masuk ke status `RECOVERY_REQUIRED` agar stok tidak langsung dialokasikan ulang.
- HiveMind storage lock melindungi chest atau barrel dari transaksi paralel.
- Transfer deposit dan withdrawal menyimpan lifecycle transaksional.
- Delta inventory bot dan storage wajib cocok dengan jumlah yang diminta sebelum transfer dinyatakan selesai.
- Kegagalan tetap disimpan sebagai record audit dengan kode dan alasan spesifik.

## Lifecycle transfer

Transfer deposit menggunakan alur:

```text
CREATED → LOCK_ACQUIRED → DEPOSITING → VERIFYING → COMPLETED
```

Transfer withdrawal menggunakan alur:

```text
CREATED → LOCK_ACQUIRED → WITHDRAWING → VERIFYING → COMPLETED
```

Kegagalan pada tahap mana pun menghasilkan status `FAILED`. Kode kegagalan yang dapat dicatat meliputi `PATHFINDER_FAILED`, `PARTIAL_TRANSFER`, `VERIFICATION_FAILED`, `DESTINATION_FULL`, `SOURCE_CHANGED`, `LOCK_TIMEOUT`, dan `OPERATION_FAILED`.

## Observability

Dashboard Logistics menampilkan:

- Jumlah reservation aktif
- Transfer yang sedang berjalan
- Reservation yang membutuhkan recovery
- Storage lock aktif
- Inventory tersedia setelah dikurangi reservation
- Riwayat transfer berhasil dan gagal
- Timeline lifecycle reservation dan transfer

Endpoint monitoring yang tersedia:

- `GET /api/v1/logistics/status`
- `GET /api/v1/logistics/storages`
- `GET /api/v1/logistics/reservations`
- `GET /api/v1/logistics/transfers`
- `GET /api/v1/logistics/timeline`
- `GET /api/v1/logistics/locks`
- `GET /api/v1/hivemind/locks`

## Verifikasi release

- Concurrent reservation diuji agar tidak terjadi double-spending.
- Reservation expiration diuji bersama event auditnya.
- Partial transfer dan verification mismatch diuji sebagai kegagalan.
- Lock contention dan pathfinding failure diuji serta disimpan ke audit transfer.
- Seluruh suite berisi 78 test lulus saat release dibuat.
- Health check aplikasi menghasilkan status `HEALTHY`.

## Di luar scope

Warehouse role, policy engine, courier queue lanjutan, route planner, forecasting, dan automatic rebalancing tetap menjadi target `0.7.1`. Territory system tetap berada di milestone `0.8.0` dan belum dimulai pada release ini.
