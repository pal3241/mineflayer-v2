# 0.7.1 — Intelligent Death Recovery

Release `0.7.1` menutup gap antara logistik transaksional dan sistem recovery item ketika bot mati di dunia. Fokus utama release ini adalah membangun alur recovery yang aman, terukur, dan dapat diaudit sebelum item yang tersisa benar-benar hilang karena despawn atau ancaman lingkungan.

## Perubahan utama

- Recovery job dibuat secara otomatis dari death manifest dan evaluasi item yang selamat.
- Setiap item dinilai berdasarkan prioritas dasar, scarcity, demand, dan ukuran biaya recovery.
- Recovery job membatasi item yang benar-benar bernilai dan mengabaikan item kecil atau tidak layak diekstraksi.
- Setiap job memelihara budget despawn, margin keamanan, dan state lifecycle yang dapat dilacak.
- Bot recovery dipilih berdasarkan kelayakan, jarak, status hidup, kapasitas inventori, dan tingkat bahaya area.
- Verifikasi akhir membandingkan delta inventori dengan item yang diambil agar hanya item valid yang diklaim berhasil dipulihkan.
- Recovery yang gagal, kadaluarsa, atau tidak layak dicatat sebagai status terminal agar tidak mengulang pekerjaan yang sama.
- Dashboard Recovery menampilkan KPI, job aktif, timeline, item yang diabaikan, serta policy settings runtime.

## Lifecycle recovery job

Alur utama mengikuti:

```text
DETECTED → PENDING → EVALUATING → ASSIGNED → TRAVELLING → SEARCHING → COLLECTING → VERIFYING → RECOVERED
```

Cabang kegagalan dapat masuk ke `REASSIGN_REQUIRED`, `FAILED`, `EXPIRED`, `CANCELLED`, atau `UNRECOVERABLE` sesuai kondisi yang terjadi. State `PARTIAL` dan `PARTIAL_RECONCILED` dipakai saat sebagian item berhasil dikembalikan namun sebagian sisanya harus diputuskan sebagai kerugian yang dapat diterima.

## Policy default

Policy default yang diterapkan:

- `enabled: true`
- `maxAttempts: 3`
- `minScore: 40`
- `optionalScore: 20`
- `urgentScore: 70`
- `despawnTicks: 6000`
- `safetyMarginTicks: 600`
- `maxDistance: 2000`
- `dangerLimit: 0.75`

Semua nilai ini dapat diubah melalui endpoint settings dan dipantau langsung di dashboard Recovery.

## Endpoint dan dashboard

Endpoint yang dipakai untuk release ini:

- `PATCH /api/v1/settings/recovery`
- `GET /api/v1/recovery/dashboard`

Dashboard Recovery menampilkan:

- jumlah job aktif
- recovery dengan prioritas urgent
- item berhasil dipulihkan
- kehilangan permanen
- item yang sengaja diabaikan
- tingkat keberhasilan
- timeline event recovery
- pengaturan runtime yang sedang aktif

## Verifikasi release

- Recovery configuration route dan dashboard route diuji melalui API integration test.
- Recovery job service diuji untuk validasi state, limit percobaan, dan kalibrasi item wajib.
- Despawn budget, item evaluator, recovery selector, dan verifier memiliki suite unit terpisah.
- Seluruh suite saat release dibuat menghasilkan 94 test dengan 93 lulus, 1 kegagalan sebelum patching kritis, lalu 3 API regression test lulus pada verifikasi akhir.
- Health check aplikasi tetap menghasilkan `HEALTHY` di mode test dan produk.

## Di luar scope

Recovery berbasis world event, autonomous follow-up dari bot lain, dan koordinasi multi-bot lintas server tetap berada pada milestone yang lebih tinggi. Release ini difokuskan pada `death recovery` yang deterministik, aman, dan terukur dalam satu runtime bot maupun satu lingkungan logistik.
